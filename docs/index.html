Haxe 
package;

import flixel.FlxG;
import mklib.state.State;
import mklib.layer.TileLayer;
import mklib.layer.EntityLayer;
import mklib.path.NavGridBuilder;
import mklib.path.NavGrid;

class PlayState extends State<Data.Data_Level> {
    public var tileLayer:TileLayer;
    public var entityLayer:EntityLayer;
    public var navGrid:NavGrid;

    override public function create():Void {
        super.create();

        // 1. Nape-Physikraum mit Schwerkraft initialisieren
        napeInit(0, 300);

        // 2. Kachelebene aus LDtk rendern
        tileLayer = new TileLayer(data.l_Tiles.identifier);
        add(tileLayer);

        // 3. Entities im Package "entities.*" automatisch instanziieren
        entityLayer = new EntityLayer(data.l_Entities);
        add(entityLayer);

        // 4. A*-NavGrid automatisch aus Leveldaten bauen
        navGrid = NavGridBuilder.autoBuild(data);
    }
}

Erstelle die Datei source/Data.hx. Das Makro analysiert deine map.ldtk-Datei zur Compile-Zeit und erzeugt typisierte Klassen:

package;

/**

 * ein und generiert typisierte Klassen und Enums für alle Level, Layer und Entities.
 */
private typedef _Tmp = haxe.macro.MacroType<[ ldtk.Project.build("assets/data/map.ldtk") ]>;

GPU-Lighting Integration

Lichtquellen (Point, Spot, Torch, Glow) werden direkt aus LDtk-Entity-Feldern mit Radius, Farbe und Flackern erzeugt.

1. 🏛️ Architektur & Workflow

In mklib sind alle Leveldaten deklarativ im LDtk Level-Editor aufgebaut. Das offizielle Haxe LDtk-Makro (Data.hx) liest die Projektdatei zur Compile-Zeit aus und generiert typsichere Strukturen. Zur Laufzeit übernimmt mklib die vollautomatische Instanziierung:

Haxe Workflow 
class PlayState extends State<Data.Data_Level> {
    override public function create():Void {
        super.create();

        // 1. Initialisiert Nape & erzeugt CbTypes aus dem LDtk-Enum "Tags"
        napeInit(0, 0);

        // 2. Rendert Kachelebenen (Tiles / AutoLayer)
        add(new TileLayer(data.l_Tiles.identifier));
        add(new TileLayer(data.l_Props.identifier));

        // 3. Instanziiert alle Entities (sucht Klassen in "entities.*")
        add(new EntityLayer(data.l_Entities));
        add(new EntityLayer(data.l_HeroLayer));

        // 4. Erzeugt A* Navigationsraster aus IntGrid und Kacheln
        var navGrid = NavGridBuilder.autoBuild(data);

        // 5. Lädt GPU-Lichter (Point, Spot, Torch, Glow) aus LDtk-Entities
        var lighting = new LightingSystem(0xFF101018, 1.5);
        lighting.loadFromLevel(data);
        add(lighting);
    }
}

3. 🗺️ Layer-Typen in LDtk

In LDtk können drei Layer-Kategorien definiert werden, die von mklib unterschiedlich verarbeitet werden:

LDtk Layer-Typ Empfohlene Namen mklib Klasse Funktionsweise & Details

6. 💻 Eigene Custom Fields im Haxe-Code abfragen

Du kannst beliebige eigene Felder in LDtk anlegen (z. B. hp, dialogKey, targetLevel, isLocked, patrolPoints) und im Haxe-Code auf zwei Arten abrufen:

Custom Entity mit getField() 
package entities;

import mklib.entity.EntitySprite;
import ldtk.Entity;

@:keep
class Chest extends EntitySprite {
    public var isLocked:Bool = false;
    public var lootItemId:String = "potion";
    public var lootCount:Int = 1;

    public function new(entity:ldtk.Entity) {
        super(entity);

        if (hasField("isLocked")) {
            isLocked = getField("isLocked");
        }
        if (hasField("lootItemId")) {
            lootItemId = getField("lootItemId");
        }
        if (hasField("lootCount")) {
            lootCount = getField("lootCount");
        }

1. 🏛️ Architecture & Workflow

In mklib, all level data is built declaratively in the LDtk Level Editor. The official Haxe LDtk macro (Data.hx) reads the project file at compile-time and generates type-safe structures. At runtime, mklib handles automated instantiation:

Haxe Workflow 
class PlayState extends State<Data.Data_Level> {
    override public function create():Void {
        super.create();

        // 1. Initializes Nape & registers CbTypes from the LDtk enum "Tags"
        napeInit(0, 0);

        // 2. Renders tile layers (Tiles / AutoLayer)
        add(new TileLayer(data.l_Tiles.identifier));
        add(new TileLayer(data.l_Props.identifier));

        // 3. Instantiates all entities (scans package "entities.*")
        add(new EntityLayer(data.l_Entities));
        add(new EntityLayer(data.l_HeroLayer));

        // 4. Builds A* navigation grid from IntGrid and tile layers
        var navGrid = NavGridBuilder.autoBuild(data);

        // 5. Loads GPU lights (Point, Spot, Torch, Glow) from LDtk entities
        var lighting = new LightingSystem(0xFF101018, 1.5);
        lighting.loadFromLevel(data);
        add(lighting);
    }
}

3. LDtk-Workflow: Das Enum Animations (Best Practice)

Um Tippfehler zu vermeiden und im Level-Editor ein komfortables Dropdown-Menü bereitzustellen, empfiehlt sich in LDtk die Verwendung eines Enums:

  1. Enum anlegen: Erstelle in LDtk unter Project Settings → Enums ein Enum namens Animations mit den Namen der Animationsdateien (z. B. Fire, Hero, Platform).
  2. Entity-Feld definieren: Füge der gewünschten Entity-Definition ein Feld namens Animations vom Typ Enum.Animations hinzu.
  3. Level platzieren: Wähle beim Platzieren der Entity im Level-Editor einfach die gewünschte Animation aus dem Dropdown-Menü aus.
ℹ️
Automatische Bindung: EntitySprite und EntityNapeSprite prüfen im Basis-Konstruktor automatisch mit hasField("Animations"), lesen den gewählten Enum-Wert als String aus (z. B. "Fire") und laden die Grafik sowie Clips direkt aus AnimationRegistry.db.

Statische Methoden zur Registrierung aller Kollisions- und Sensor-Events.

Physische Kollisionen (InteractionType.COLLISION)

Methode Signatur Ereignis Beschreibung
addCollisionBeginListener (t1:String, t2:String, handler:InteractionCallback->Void) CbEvent.BEGIN Wird aufgerufen, sobald sich zwei Körper mit t1 und t2 berühren.

Sensor-Überlappungen (InteractionType.SENSOR)

Methode Signatur Ereignis Beschreibung
addSensorBeginListener (t1:String, t2:String, handler:InteractionCallback->Void) CbEvent.BEGIN Überlappung zwischen t1 und t2 beginnt.

Pixelgenaue Kollisionen (Pixel-Perfect Collision)

💡 GPU-Shader-Lighting-System (mklib.light.*)

Hardwarebeschleunigte 2D-Echtzeitbeleuchtung auf GPU-Shader-Basis mit Viewport-Culling, 5 Licht-Typen und nativer LDtk Custom-Properties-Steuerung.

🌟 Features & Highlights

  • ⚡ GLSL-Shader auf der GPU: Berechnet bis zu 32 dynamische Lichter gleichzeitig in einem einzigen Render-Pass mit sanften Hermite-Dämpfungskurven (smoothstep).
  • 🎯 5 Spezialisierte Licht-Typen:
    • PointLight: 360°-Rundumlicht mit anpassbarem 100%-Helligkeitskern (innerRadius).
    • SpotLight: Gerichteter Scheinwerfer mit Abstrahlwinkel, Gesamtkegel und weichem Fokusübergang (innerAngle).
    • TorchLight: Naturgetreues Fackelflackern durch multi-harmonische Wellen und Flammen-Wobble (flameJitter).
    • GlowLight: Sanft atmendes Magie-/Aura-Licht mit konfigurierbaren Min/Max-Bereichen und Puls-Geschwindigkeit.
    • DirectionalLight: Globales Sonnen-, Mond- und Umgebungslicht mit Einfallswinkel.
  • 🚀 Automatisches Frustum-Culling: In großen Welten werden pro Frame nur die aktuell im Kamerabereich sichtbaren Lichter an die GPU gesendet.
  • 🧲 Zielverfolgung (follow): Lichter folgen Spielfiguren oder Objekten automatisch mit konfigurierbarem Versatz.
  • 🗺️ Volle LDtk-Integration: Alle Lichteigenschaften können direkt in LDtk als Custom Fields definiert und automatisiert geladen werden.

🚀 Code-Beispiele

1. Grundlegendes Setup im PlayState

Haxe 
package;

import mklib.state.State;
import mklib.light.LightingSystem;

class PlayState extends State<Data.Data_Level> {
    public var lighting:LightingSystem;

    override public function create():Void {
        super.create();

        // 1. LightingSystem mit dunkler Nacht-Atmosphäre erstellen (Overlay-Sprite)
        lighting = new LightingSystem(0xFF141424, 0.2);

        // 2. Fackellicht erzeugen
        var torch = lighting.createTorchLight(100, 100, 120, 0xFFFFAA44, 1.0);

        // 3. Scheinwerfer erzeugen
        var spot = lighting.createSpotLight(200, 80, 160, 90, 45, 0xFFFFFFFF);

        // 4. Pulsierenden Kristall erzeugen
        var glow = lighting.createGlowLight(350, 120, 30, 70, 0xFF55AAFF, 0.3, 1.0, 2.0);

        // 5. Zum State hinzufügen
        add(lighting);
    }
}

1. Begrenzte Wasserfläche mit Position & Größe (Kamera-Filter)

Definiert ein fixes Wasser-Rechteck in Weltkoordinaten. Außerhalb bleibt die Spielwelt völlig normal, innerhalb spiegelt sich alles oberhalb mit Wellen:

Haxe 
package;

import flixel.FlxG;
import openfl.filters.ShaderFilter;
import mklib.state.State;
import mklib.effect.shader.WaterReflectionShader;

class PlayState extends State<Data.Data_Level> {
    public var waterShader:WaterReflectionShader;

    override public function create():Void {
        super.create();

        // 1. Shader instanziieren
        waterShader = new WaterReflectionShader();

        // 2. Wasserfläche definieren: Welt-X=0, Welt-Y=120, Breite=320px, Tiefe=80px
        waterShader.setWaterArea(0, 120, 320, 80);

        // 3. Wellen-Dynamik einstellen (Speed, Frequenz, Amplitude, Kreuzwellen)
        waterShader.setWaveParams(2.8, 30.0, 0.012, 0.5);

        // 4. Wassertönung und Schaumkante einstellen
        waterShader.setWaterColor(0x3366AA, 0.45);
        waterShader.setFoam(0.008, 0xFFFFFF);

        // 5. Als Kamerafilter aktivieren
        FlxG.camera.filters = [new ShaderFilter(waterShader)];
    }

    override public function update(elapsed:Float):Void {
        super.update(elapsed);

        // WICHTIG: Zählt Wellenzeit hoch und synchronisiert Kamera-Scroll/Zoom automatisch
        if (waterShader != null) {
            waterShader.update(elapsed);
        }
    }
}
