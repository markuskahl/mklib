Minimalbeispiel

Haxe 
package;

import flixel.FlxG;
import mklib.state.State;
import mklib.layer.TileLayer;
import mklib.layer.EntityLayer;
import mklib.path.NavGridBuilder;
import mklib.path.NavGrid;

class PlayState extends State<Data.Data_Level> {
    public var tileLayer:TileLayer;
    public var entityLayer:EntityLayer;
    public var navGrid:NavGrid;

    override public function create():Void {
        super.create();

        // 1. Nape-Physikraum mit Schwerkraft initialisieren
        napeInit(0, 300);

        // 2. Kachelebene aus LDtk rendern
        tileLayer = new TileLayer(data.l_Tiles.identifier);
        add(tileLayer);

        // 3. Entities im Package "entities.*" automatisch instanziieren
        entityLayer = new EntityLayer(data.l_Entities);
        add(entityLayer);

        // 4. A*-NavGrid automatisch aus Leveldaten bauen
        navGrid = NavGridBuilder.autoBuild(data);
    }
}

🚀 Schnellstart & Einrichtung

Schritt-für-Schritt-Anleitung zur Installation und Einbindung in dein HaxeFlixel-Projekt.

1. Abhängigkeiten in Project.xml

Füge mklib und die benötigten Bibliotheken zu deiner Project.xml hinzu:

XML 
<haxelib name="openfl" />
<haxelib name="flixel" />
<haxelib name="flixel-addons" />
<haxelib name="nape-haxe4" />
<haxelib name="ldtk-haxe-api" />
<haxelib name="mklib" />

2. LDtk Makro-Setup (Data.hx)

Erstelle die Datei source/Data.hx. Das Makro analysiert deine map.ldtk-Datei zur Compile-Zeit und erzeugt typisierte Klassen:

Haxe 
package;

/**
 * LDtk-Makro-Kompilierung: Liest zur Compile-Zeit die Datei "assets/data/map.ldtk"
 * ein und generiert typisierte Klassen und Enums für alle Level, Layer und Entities.
 */
private typedef _Tmp = haxe.macro.MacroType<[ ldtk.Project.build("assets/data/map.ldtk") ]>;

3. Spielstart in Main.hx

Haxe 
package;

import flixel.FlxGame;
import openfl.display.Sprite;

/**
 * Haupteinstiegspunkt der Anwendung.
 */
class Main extends Sprite {
    public function new() {
        super();
        addChild(new FlxGame(320, 180, PlayState, 60, 60, true, false));
    }

🎬 Animationssystem & Makros (mklib.animation.* & mklib.macro.*)

Automatisiertes Compile-Time-Laden von JSON-Spritesheet-Animationen ohne Laufzeit-Overhead.

1. Übersicht & Funktionsweise

Das Animationssystem von mklib besteht aus typsicheren Datenstrukturen (AnimationTypes), einem Compile-Time-Makro (AnimationBuilder) und einer zentralen Datenbank (AnimationRegistry).

📁

JSON Definitions

Clips, Frameraten und Rastermaße werden als übersichtliche .json-Dateien in assets/data/animations/ abgelegt.

⚡

Compile-Time Macro

AnimationBuilder.buildDatabase() liest alle JSONs beim Kompilieren ein, normalisiert Pfade und erzeugt ein getyptes Map-Literal.

🚀

Zero Runtime Cost

Kein JSON-Parsing zur Laufzeit. Entities greifen direkt auf die typisierte AnimationRegistry.db zu.

2. Datenstrukturen (mklib.animation.AnimationTypes)

FrameConfig

Konfiguriert Kachelabmessungen und Abstände auf dem Spritesheet.

Feld Typ Optional Beschreibung
width Int Nein Breite eines einzelnen Frames in Pixeln.
height Int Nein Höhe eines einzelnen Frames in Pixeln.
spacing Null<Int> Ja Abstand zwischen Frames in Pixeln.
margin Null<Int> Ja Äußerer Rand des Spritesheets in Pixeln.

AnimationClip

Definiert einen Animationsabschnitt mit Bildfolge, Geschwindigkeit und Wiederholung.

Feld Typ Optional Beschreibung
name String Nein Name des Clips (z. B. "burn", "walk").
fps Int Nein Abspielgeschwindigkeit (Frames pro Sekunde).
loop Bool Nein Endlosschleife aktivieren (true/false).
flipX Bool Nein Horizontale Spiegelung der Frames.
flipY Bool Nein Vertikale Spiegelung der Frames.
frames Array<Int> Nein Liste der Frame-Indizes (z. B. [0, 1, 2, 3]).

SpriteSheetData

Vollständiger Datensatz für ein animiertes Spritesheet.

Feld Typ Optional Beschreibung
imagePath String Nein Pfad zur Grafikdatei (z. B. "assets/tilesets/Fire.png").
config FrameConfig Nein Kachel- und Rastereinstellungen.
animations Array<AnimationClip> Nein Liste aller definierten Clips.
defaultAnimation String Nein Name des standardmäßig abzuspielenden Clips.

3. Compile-Time-Makro (mklib.macro.AnimationBuilder)

Methode Signatur Rückgabe Beschreibung
buildDatabase (folderPath:String):Expr Expr (Makro) Liest alle .json-Dateien im Ordner zur Compile-Zeit ein, normalisiert Asset-Pfade und generiert eine Map<String, SpriteSheetData>.

⚡ Physik & Sensoren (mklib.physic.* & mklib.tools.Tags)

Methode Signatur Rückgabe Beschreibung

2. Listener (mklib.physic.Listener)

Statische Methoden zur Registrierung aller Kollisions- und Sensor-Events.

Physische Kollisionen (InteractionType.COLLISION)

Methode Signatur Ereignis Beschreibung
addCollisionBeginListener (t1:String, t2:String, handler:InteractionCallback->Void) CbEvent.BEGIN Wird aufgerufen, sobald sich zwei Körper mit t1 und t2 berühren.
addCollisionEndListener (t1:String, t2:String, handler:InteractionCallback->Void) CbEvent.END Wird aufgerufen, sobald der Kontakt zwischen t1 und t2 abreißt.
addCollisionOngoingListener (t1:String, t2:String, handler:InteractionCallback->Void) CbEvent.ONGOING Wird in jedem Physik-Tick aufgerufen, solange t1 und t2 in Kontakt stehen.

Sensor-Überlappungen (InteractionType.SENSOR)

Methode Signatur Ereignis Beschreibung
addSensorBeginListener (t1:String, t2:String, handler:InteractionCallback->Void) CbEvent.BEGIN Überlappung zwischen t1 und t2 beginnt.
addSensorEndListener (t1:String, t2:String, handler:InteractionCallback->Void) CbEvent.END Überlappung zwischen t1 und t2 endet.
addSensorOngoingListener (t1:String, t2:String, handler:InteractionCallback->Void) CbEvent.ONGOING Überlappung zwischen t1 und t2 dauert an.
addSensorBeginListenerANY (t1:String, handler:InteractionCallback->Void) CbEvent.BEGIN t1 überlappt mit beliebigem anderen Körper (CbType.ANY_BODY).
addSensorEndListenerANY (t1:String, handler:InteractionCallback->Void) CbEvent.END t1 verlässt Überlappung mit beliebigem anderen Körper.
addSensorOngoingListenerANY (t1:String, handler:InteractionCallback->Void) CbEvent.ONGOING t1 überlappt andauernd mit beliebigem anderen Körper.

💡 GPU-Shader-Lighting-System (mklib.light.*)

Hardwarebeschleunigte 2D-Echtzeitbeleuchtung auf GPU-Shader-Basis mit Viewport-Culling, 5 Licht-Typen und nativer LDtk Custom-Properties-Steuerung.

🌟 Features & Highlights

  • ⚡ GLSL-Shader auf der GPU: Berechnet bis zu 32 dynamische Lichter gleichzeitig in einem einzigen Render-Pass mit sanften Hermite-Dämpfungskurven (smoothstep).
  • 🎯 5 Spezialisierte Licht-Typen:
    • PointLight: 360°-Rundumlicht mit anpassbarem 100%-Helligkeitskern (innerRadius).
    • SpotLight: Gerichteter Scheinwerfer mit Abstrahlwinkel, Gesamtkegel und weichem Fokusübergang (innerAngle).
    • TorchLight: Naturgetreues Fackelflackern durch multi-harmonische Wellen und Flammen-Wobble (flameJitter).
    • GlowLight: Sanft atmendes Magie-/Aura-Licht mit konfigurierbaren Min/Max-Bereichen und Puls-Geschwindigkeit.
    • DirectionalLight: Globales Sonnen-, Mond- und Umgebungslicht mit Einfallswinkel.
  • 🚀 Automatisches Frustum-Culling: In großen Welten werden pro Frame nur die aktuell im Kamerabereich sichtbaren Lichter an die GPU gesendet.
  • 🧲 Zielverfolgung (follow): Lichter folgen Spielfiguren oder Objekten automatisch mit konfigurierbarem Versatz.
  • 🗺️ Volle LDtk-Integration: Alle Lichteigenschaften können direkt in LDtk als Custom Fields definiert und automatisiert geladen werden.

🚀 Code-Beispiele

1. Grundlegendes Setup im PlayState

Haxe 
package;

import mklib.state.State;
import mklib.light.LightingSystem;

class PlayState extends State<Data.Data_Level> {
    public var lighting:LightingSystem;

    override public function create():Void {
        super.create();

        // 1. LightingSystem mit dunkler Nacht-Atmosphäre erstellen (Overlay-Sprite)
        lighting = new LightingSystem(0xFF141424, 0.2);

        // 2. Fackellicht erzeugen
        var torch = lighting.createTorchLight(100, 100, 120, 0xFFFFAA44, 1.0);

        // 3. Scheinwerfer erzeugen
        var spot = lighting.createSpotLight(200, 80, 160, 90, 45, 0xFFFFFFFF);

        // 4. Pulsierenden Kristall erzeugen
        var glow = lighting.createGlowLight(350, 120, 30, 70, 0xFF55AAFF, 0.3, 1.0, 2.0);

        // 5. Zum State hinzufügen
        add(lighting);
    }
}

🌊 Wasser-Reflexions- & Wellen-Shader (mklib.effect.*)

Hardwarebeschleunigte GPU-Shader und spezialisierte Spielobjekte für dynamische Wasseroberflächen, Wellenverzerrungen und Entity-Reflexionen.

⚡

GPU Fragment-Shader

Berechnet Multi-Sinus- und Cosinus-Wellenverzerrungen direkt auf der Grafikkarte für maximale Frameraten.

📐

Feste Wasserflächen

setWaterArea(x, y, w, h) definiert ein fixes Wasser-Rechteck in Weltkoordinaten mit automatischem Kamera-Tracking.

🔄

3 Betriebsmodi

Vertikale Wasseroberfläche, horizontaler Spiegel (Portale/Wände) und reine Wellenverzerrung für Sprites.

🦆

Entity-Reflexion

EntityWaterReflection spiegelt Spielfiguren automatisch an deren Fußkante und synchronisiert Animationen.

🧭 Welcher Ansatz für welchen Zweck?

Werkzeug / Komponente Einsatzbereich Vorteil
WaterReflectionShader
(Kamera-Filter)		 Seen, Teiche, Flüsse, Meere im Level mit definierter Position & Größe (setWaterArea) oder Vollbild-Wasserlinie. GPU-Echtzeit: Spiegelt alle Kacheln, Entities, Deko und Lichter automatisch mit 0 CPU-Overhead.
EntityWaterReflection
(Begleiter-Sprite)		 Einzelne Spielfiguren (Hero, NPCs, Monster), die im Wasser waten oder schwimmen. Exakte Kontrolle: Spiegelt Frames und Animationen live unter den Füßen mit sanftem Wogen.
WaterReflectionPlane
(Platziertes FlxSprite)		 Eigenständiges Spielobjekt (FlxSprite) an festen Weltkoordinaten. Verhält sich wie ein normales Flixel-Sprite in Gruppen und Render-Hierarchien.

🚀 Code-Beispiele & Schnellstart

1. Begrenzte Wasserfläche mit Position & Größe (Kamera-Filter)

Definiert ein fixes Wasser-Rechteck in Weltkoordinaten. Außerhalb bleibt die Spielwelt völlig normal, innerhalb spiegelt sich alles oberhalb mit Wellen:

Haxe 
package;

import flixel.FlxG;
import openfl.filters.ShaderFilter;
import mklib.state.State;
import mklib.effect.shader.WaterReflectionShader;

class PlayState extends State<Data.Data_Level> {
    public var waterShader:WaterReflectionShader;

    override public function create():Void {
        super.create();

        // 1. Shader instanziieren
        waterShader = new WaterReflectionShader();

        // 2. Wasserfläche definieren: Welt-X=0, Welt-Y=120, Breite=320px, Tiefe=80px
        waterShader.setWaterArea(0, 120, 320, 80);

        // 3. Wellen-Dynamik einstellen (Speed, Frequenz, Amplitude, Kreuzwellen)
        waterShader.setWaveParams(2.8, 30.0, 0.012, 0.5);

        // 4. Wassertönung und Schaumkante einstellen
        waterShader.setWaterColor(0x3366AA, 0.45);
        waterShader.setFoam(0.008, 0xFFFFFF);

        // 5. Als Kamerafilter aktivieren
        FlxG.camera.filters = [new ShaderFilter(waterShader)];
    }

    override public function update(elapsed:Float):Void {
        super.update(elapsed);

        // WICHTIG: Zählt Wellenzeit hoch und synchronisiert Kamera-Scroll/Zoom automatisch
        if (waterShader != null) {
            waterShader.update(elapsed);
        }
    }
}

2. Vollbild-Wasserspiegelung (Ab relativer Wasserlinie)

Ideal für 2D-Platformer mit durchgehendem Meer/Wasser am unteren Bildschirmrand:

Haxe 
// Wasserlinie bei 65% der Bildschirmhöhe festlegen (0.0 = oben, 1.0 = unten)

3. Entity-Wasserreflexion (Spielfiguren-Begleiter)

Erzeugt eine dynamische Wasser-Reflexion für den Spieler (Hero) oder NPCs:

Haxe 
package entities;

import mklib.entity.EntityNapeSprite;
import mklib.effect.EntityWaterReflection;
import ldtk.Entity;

class Hero extends EntityNapeSprite {
    public var waterReflection:EntityWaterReflection;

    public function new(entity:ldtk.Entity) {
        super(entity);

        // 1. Wasserreflexion für diesen Hero erstellen (Alpha=0.6, Farbe=0x3366AA)
        waterReflection = new EntityWaterReflection(this, 0.6, 0x3366AA);

        // 2. Wellenparameter für die Spielfigur einstellen
        waterReflection.setWaveParams(4.0, 20.0, 0.08);

        // 3. Perspektivische Stauchung (z. B. 0.85)
        waterReflection.verticalScale = 0.85;

        // 4. Zum State hinzufügen
        if (state != null) {
            state.add(waterReflection);
        }
    }
}

4. Horizontaler Spiegel-Modus (HORIZONTAL_MIRROR)

Für magische Wandspiegel, Raumportale oder seitliche Wasserwände:

Haxe 
import mklib.effect.WaterReflectionMode;

var mirrorShader = new WaterReflectionShader();

// 1. Modus auf horizontalen Spiegel schalten:
mirrorShader.setMode(WaterReflectionMode.HORIZONTAL_MIRROR);

// 2. Spiegelachse bei 50% der Bildschirmbreite (X-Achse):
mirrorShader.setWaterLevel(0.5);
mirrorShader.setWaveParams(2.0, 20.0, 0.006);

FlxG.camera.filters = [new ShaderFilter(mirrorShader)];
