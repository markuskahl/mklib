Minimalbeispiel

Haxe 
package;

import flixel.FlxG;
import mklib.state.State;
import mklib.layer.TileLayer;
import mklib.layer.EntityLayer;
import mklib.path.NavGridBuilder;
import mklib.path.NavGrid;

class PlayState extends State<Data.Data_Level> {
    public var tileLayer:TileLayer;
    public var entityLayer:EntityLayer;
    public var navGrid:NavGrid;

    override public function create():Void {
        super.create();

        // 1. Nape-Physikraum mit Schwerkraft initialisieren
        napeInit(0, 300);

        // 2. Kachelebene aus LDtk rendern
        tileLayer = new TileLayer(data.l_Tiles.identifier);
        add(tileLayer);

        // 3. Entities im Package "entities.*" automatisch instanziieren
        entityLayer = new EntityLayer(data.l_Entities);
        add(entityLayer);

        // 4. A*-NavGrid automatisch aus Leveldaten bauen
        navGrid = NavGridBuilder.autoBuild(data);
    }
}

🚀 Schnellstart & Einrichtung

Schritt-für-Schritt-Anleitung zur Installation und Einbindung in dein HaxeFlixel-Projekt.

1. Abhängigkeiten in Project.xml

Füge mklib und die benötigten Bibliotheken zu deiner Project.xml hinzu:

XML 
<haxelib name="openfl" />
<haxelib name="flixel" />
<haxelib name="flixel-addons" />
<haxelib name="nape-haxe4" />
<haxelib name="ldtk-haxe-api" />
<haxelib name="deepnightLibs" />
<haxelib name="mklib" />

2. LDtk Makro-Setup (Data.hx)

Erstelle die Datei source/Data.hx. Das Makro analysiert deine map.ldtk-Datei zur Compile-Zeit und erzeugt typisierte Klassen:

Haxe 
package;

/**
 * LDtk-Makro-Kompilierung: Liest zur Compile-Zeit die Datei "assets/data/map.ldtk"
 * ein und generiert typisierte Klassen und Enums für alle Level, Layer und Entities.
 */
private typedef _Tmp = haxe.macro.MacroType<[ ldtk.Project.build("assets/data/map.ldtk") ]>;

3. Spielstart in Main.hx

Haxe 
package;

import flixel.FlxGame;
import openfl.display.Sprite;

/**
 * Haupteinstiegspunkt der Anwendung.
 */
class Main extends Sprite {
    public function new() {
        super();
        addChild(new FlxGame(320, 180, PlayState, 60, 60, true, false));
    }
}

Tipp zur Dead-Code-Elimination (DCE): Versehe deine dynamisch geladenen Entity-Klassen stets mit der Annotation @:keep, damit der Haxe-Compiler sie bei Release-Builds nicht wegoptimiert.

🎬 Animationssystem & Makros (mklib.animation.* & mklib.macro.*)

Automatisiertes Compile-Time-Laden von JSON-Spritesheet-Animationen ohne Laufzeit-Overhead.

1. Übersicht & Funktionsweise

Das Animationssystem von mklib besteht aus typsicheren Datenstrukturen (AnimationTypes), einem Compile-Time-Makro (AnimationBuilder) und einer zentralen Datenbank (AnimationRegistry).

📁

JSON Definitions

Clips, Frameraten und Rastermaße werden als übersichtliche .json-Dateien in assets/data/animations/ abgelegt.

⚡

Compile-Time Macro

AnimationBuilder.buildDatabase() liest alle JSONs beim Kompilieren ein, normalisiert Pfade und erzeugt ein getyptes Map-Literal.

🚀

Zero Runtime Cost

Kein JSON-Parsing zur Laufzeit. Entities greifen direkt auf die typisierte AnimationRegistry.db zu.

2. Datenstrukturen (mklib.animation.AnimationTypes)

FrameConfig

Konfiguriert Kachelabmessungen und Abstände auf dem Spritesheet.

Feld Typ Optional Beschreibung
width Int Nein Breite eines einzelnen Frames in Pixeln.
height Int Nein Höhe eines einzelnen Frames in Pixeln.
spacing Null<Int> Ja Abstand zwischen Frames in Pixeln.
margin Null<Int> Ja Äußerer Rand des Spritesheets in Pixeln.

AnimationClip

Definiert einen Animationsabschnitt mit Bildfolge, Geschwindigkeit und Wiederholung.

Feld Typ Optional Beschreibung
name String Nein Name des Clips (z. B. "burn", "walk").
fps Int Nein Abspielgeschwindigkeit (Frames pro Sekunde).
loop Bool Nein Endlosschleife aktivieren (true/false).
flipX Bool Nein Horizontale Spiegelung der Frames.
flipY Bool Nein Vertikale Spiegelung der Frames.
frames Array<Int> Nein Liste der Frame-Indizes (z. B. [0, 1, 2, 3]).

SpriteSheetData

Vollständiger Datensatz für ein animiertes Spritesheet.

Feld Typ Optional Beschreibung
imagePath String Nein Pfad zur Grafikdatei (z. B. "assets/tilesets/Fire.png").
config FrameConfig Nein Kachel- und Rastereinstellungen.
animations Array<AnimationClip> Nein Liste aller definierten Clips.
defaultAnimation String Nein Name des standardmäßig abzuspielenden Clips.

3. Compile-Time-Makro (mklib.macro.AnimationBuilder)

Methode Signatur Rückgabe Beschreibung
buildDatabase (folderPath:String):Expr Expr (Makro) Liest alle .json-Dateien im Ordner zur Compile-Zeit ein, normalisiert Asset-Pfade und generiert eine Map<String, SpriteSheetData>.

⚡ Physik & Sensoren (mklib.physic.* & mklib.tools.Tags)

Einfache Registrierung von Kollisionen und Sensor-Überlappungen ohne manuelle CbType-Verwaltung.

1. Tags (mklib.tools.Tags)

Statische Hilfsklasse zum Abfragen von CbType-Objekten aus dem aktuellen `State`.

Methode Signatur Rückgabe Beschreibung
get (tag:String):nape.callbacks.CbType CbType Gibt den registrierten CbType für einen Tag-Namen zurück (oder null).
exist (tag:String):Bool Bool Prüft, ob der Tag im aktuellen State registriert ist.

2. Listener (mklib.physic.Listener)

Statische Methoden zur Registrierung aller Kollisions- und Sensor-Events.

Physische Kollisionen (InteractionType.COLLISION)

Methode Signatur Ereignis Beschreibung
addCollisionBeginListener (t1:String, t2:String, handler:InteractionCallback->Void) CbEvent.BEGIN Wird aufgerufen, sobald sich zwei Körper mit t1 und t2 berühren.
addCollisionEndListener (t1:String, t2:String, handler:InteractionCallback->Void) CbEvent.END Wird aufgerufen, sobald der Kontakt zwischen t1 und t2 abreißt.
addCollisionOngoingListener (t1:String, t2:String, handler:InteractionCallback->Void) CbEvent.ONGOING Wird in jedem Physik-Tick aufgerufen, solange t1 und t2 in Kontakt stehen.

Sensor-Überlappungen (InteractionType.SENSOR)

Methode Signatur Ereignis Beschreibung
addSensorBeginListener (t1:String, t2:String, handler:InteractionCallback->Void) CbEvent.BEGIN Überlappung zwischen t1 und t2 beginnt.
addSensorEndListener (t1:String, t2:String, handler:InteractionCallback->Void) CbEvent.END Überlappung zwischen t1 und t2 endet.
addSensorOngoingListener (t1:String, t2:String, handler:InteractionCallback->Void) CbEvent.ONGOING Überlappung zwischen t1 und t2 dauert an.
addSensorBeginListenerANY (t1:String, handler:InteractionCallback->Void) CbEvent.BEGIN t1 überlappt mit beliebigem anderen Körper (CbType.ANY_BODY).
addSensorEndListenerANY (t1:String, handler:InteractionCallback->Void) CbEvent.END t1 verlässt Überlappung mit beliebigem anderen Körper.
addSensorOngoingListenerANY (t1:String, handler:InteractionCallback->Void) CbEvent.ONGOING t1 überlappt andauernd mit beliebigem anderen Körper.
