mklib Dokumentation

Eine performante, moderne Haxe-Bibliothek zur nahtlosen Verbindung von HaxeFlixel, dem LDtk Level-Editor und der Nape 2D Physik-Engine.

🗺️

LDtk Integration

Automatische Kachelebenen-Darstellung und dynamische Reflection-Instanziierung von Spielfiguren.

⚡

Nape Physik & Tags

Einfaches Registrieren von Kollisions- und Sensor-Events via lesbaren Tag-Namen aus LDtk-Enums.

🧭

A* Pathfinding

2D-Wegfindung mit 4- und 8-Wege-Bewegung, Weltkoordinaten und Einheiten beliebiger Kachelgröße.

📱

Responsive Skalierung

Automatische Berechnung idealer Spielauflösungen für moderne Breitbild-Displays ohne Verzerrung.

Minimalbeispiel

Ein vollständiger Spielzustand mit automatischer Physik-, Layer- und Pathfinding-Initialisierung:

Haxe 
package;

import flixel.FlxG;
import mklib.state.State;
import mklib.layer.TileLayer;
import mklib.layer.EntityLayer;
import mklib.path.NavGridBuilder;
import mklib.path.NavGrid;

class PlayState extends State<Data.Data_Level> {
    public var tileLayer:TileLayer;
    public var entityLayer:EntityLayer;
    public var navGrid:NavGrid;

    override public function create():Void {
        super.create();

        // 1. Nape-Physikraum mit Schwerkraft initialisieren
        napeInit(0, 300);

        // 2. Kachelebene aus LDtk rendern
        tileLayer = new TileLayer(data.l_Tiles.identifier);
        add(tileLayer);

        // 3. Entities im Package "entities.*" automatisch instanziieren
        entityLayer = new EntityLayer(data.l_Entities);
        add(entityLayer);

        // 4. A*-NavGrid automatisch aus Leveldaten bauen
        navGrid = NavGridBuilder.autoBuild(data);
    }
}

🚀 Schnellstart & Einrichtung

Schritt-für-Schritt-Anleitung zur Installation und Einbindung in dein HaxeFlixel-Projekt.

1. Abhängigkeiten in Project.xml

Füge mklib und die benötigten Bibliotheken zu deiner Project.xml hinzu:

XML 
<haxelib name="openfl" />
<haxelib name="flixel" />
<haxelib name="flixel-addons" />
<haxelib name="nape-haxe4" />
<haxelib name="ldtk-haxe-api" />
<haxelib name="deepnightLibs" />
<haxelib name="mklib" />

2. LDtk Makro-Setup (Data.hx)

Erstelle die Datei source/Data.hx. Das Makro analysiert deine map.ldtk-Datei zur Compile-Zeit:

Haxe 
package;

private typedef _Tmp = haxe.macro.MacroType<[ ldtk.Project.build("assets/data/map.ldtk") ]>;

3. Spielstart in Main.hx

Haxe 
package;

import flixel.FlxGame;
import openfl.display.Sprite;

class Main extends Sprite {
    public function new() {
        super();
        addChild(new FlxGame(320, 180, PlayState, 60, 60, true, false));
    }
}
💡
Tipp: Versehe deine Entity-Klassen stets mit der Annotation @:keep, damit der Haxe-Compiler sie bei optimierten Release-Builds (DCE) nicht verwirft.

🎮 State Management (mklib.state.State)

Die generische Basisklasse für Spielzustände mit automatischer LDtk- und Nape-Anbindung.

Eigenschaften

Eigenschaft Typ Beschreibung
project ldtk.Project Die geladene LDtk-Projektinstanz.
data TLevel Die typisierten Leveldaten des aktiven Levels (z. B. data.l_Tiles).
levelName String Der Name des aktuell geladenen Levels (z. B. "Level_0").
tags Map<String, CbType> Registrierte Kollisionstags aus dem LDtk-Enum "Tags".

Wichtige Methoden

Methode Signatur Beschreibung
new (LevelName:String = "Level_0", ?projectInstance:ldtk.Project) Erstellt den State und lädt das angegebene Level aus dem LDtk-Projekt.
napeInit (gx:Int, gy:Int):Void Startet FlxNapeSpace, setzt die Gravitation und lädt CbTypes.
addCbTypes ():Void Liest das LDtk-Enum "Tags" aus und registriert CbTypes.

🧱 Layer System (mklib.layer.*)

Verwaltung und Darstellung von Kachel- und Entity-Ebenen aus LDtk.

TileLayer

Rendert LDtk-Kachelebenen (Layer_Tiles / Layer_AutoLayer) direkt in eine FlxSpriteGroup:

Haxe 
var tileLayer = new TileLayer(data.l_Tiles.identifier);
add(tileLayer);

// Bei Bedarf zur Laufzeit neu rendern:
tileLayer.render();

EntityLayer & Reflection-Mechanismus

EntityLayer durchsucht zur Laufzeit das angegebene Package (Standard: "entities") nach Klassen, deren Name dem Entity-Identifier in LDtk entspricht:

  • LDtk Entity Hero → instanziiert entities.Hero
  • LDtk Entity Platform → instanziiert entities.Platform
Haxe 
// Instanziiert alle Entities aus data.l_Entities im Package "entities":
var entityLayer = new EntityLayer(data.l_Entities, "entities");
add(entityLayer);

👾 Entities & Sprites (mklib.entity.*)

Basisklassen für visuelle und physikalische Spielobjekte.

EntitySprite vs. EntityNapeSprite

EntitySprite

Erbt von FlxSprite. Ideal für rein grafische Objekte ohne Physik (Partikel, Dekorationen, einfache Items).

EntityNapeSprite

Erbt von FlxNapeSprite. Unterstützt Physik, Shapes, automatisches Tag-Mapping (addCbType) und Zentrierung.

Code-Beispiel: Physikalische Plattform

Haxe 
package entities;

import mklib.entity.EntityNapeSprite;
import flixel.util.FlxColor;
import ldtk.Entity;

@:keep
class Platform extends EntityNapeSprite {
    public function new(entity:Entity) {
        super(entity);

        makeGraphic(entity.width, entity.height, FlxColor.RED);
        createRectangularBody(entity.width, entity.height);
        body.allowMovement = false;

        // Nape-Körper im Mittelpunkt der LDtk-Entity zentrieren:
        updateShapePosition();

        // Tags automatisch aus LDtk-Feldern ("Tag" / "Tags") übernehmen:
        addCbType();
    }
}

⚡ Physik & Sensoren (mklib.physic.*)

Einfache Registrierung von Kollisionen und Sensor-Überlappungen ohne manuelle CbType-Verwaltung.

Kollisionen vs. Sensoren

Ereignis-Typ Physischer Stoß? Einsatzbereich
COLLISION Ja (Körper prallen ab / liegen auf) Wände, Plattformen, Spielfiguren, Kisten
SENSOR Nein (Durchdringung erlaubt) Münzen, Power-ups, Trigger-Zonen, Stacheln

Verfügbare Listener-Methoden

Methode Ereignis Beschreibung
addCollisionBeginListener(t1, t2, fn) Kollision Beginn Wird beim ersten Kontakt zweier Tags aufgerufen.
addCollisionEndListener(t1, t2, fn) Kollision Ende Wird aufgerufen, sobald der Kontakt abreißt.
addSensorBeginListener(t1, t2, fn) Sensor Beginn Sensor-Überlappung zwischen zwei Tags beginnt.
addSensorBeginListenerANY(tag, fn) Sensor Beliebig Tag überlappt mit irgendeinem anderen Körper.

Code-Beispiel: Münz-Trigger

Haxe 
import mklib.physic.Listener;
import nape.callbacks.InteractionCallback;

// Registriert Sensor-Event zwischen "Player" und "Coin":
Listener.addSensorBeginListener("Player", "Coin", function(cb:InteractionCallback) {
    var coin:Coin = cast cb.int2.userData.instance;
    if (coin != null) {
        coin.kill();
        trace("Münze aufgesammelt!");
    }
});

NavGridBuilder (Raster aus LDtk erzeugen)

Erzeugt das Navigationsraster automatisch aus beliebigen LDtk-Layern:

// Automatischer Scan aller Layer des Levels:
var navGrid = NavGridBuilder.autoBuild(data);

// Pfad direkt in Pixel-Weltkoordinaten finden:
var path = AStar.findWorldPath(navGrid, player.x, player.y, targetX, targetY, 1, 1, true);

🛠️ Tools & Mathematik (mklib.tools.* & mklib.math.*)

Hilfsklassen für responsive Auflösungen und mathematische Berechnungen.

AspectRatio

Berechnet anhand der Bildschirmauflösung automatisch die optimale Spielbreite für eine feste vertikale Design-Höhe:

Haxe 
var ar = new AspectRatio();
trace('Optimale Auflösung: ${ar.width} x ${ar.height}');

addChild(new FlxGame(ar.width, ar.height, PlayState));

MathTool

Hilfsfunktion zur Rundung von Gleitkommazahlen auf feste Nachkommastellen:

Haxe 
var rounded = MathTool.floatFix(3.14159265, 2); // Ergibt 3.14
