🚀 Schnellstart & Einrichtung

Schritt-für-Schritt-Anleitung zur Installation und Einbindung in dein HaxeFlixel-Projekt.

1. Abhängigkeiten in Project.xml

Füge mklib und die benötigten Bibliotheken zu deiner Project.xml hinzu:

XML 
<haxelib name="openfl" />
<haxelib name="flixel" />
<haxelib name="flixel-addons" />
<haxelib name="nape-haxe4" />
<haxelib name="ldtk-haxe-api" />
<haxelib name="mklib" />

2. LDtk Makro-Setup (Data.hx)

Erstelle die Datei source/Data.hx. Das Makro analysiert deine map.ldtk-Datei zur Compile-Zeit und erzeugt typisierte Klassen:

Haxe 
package;

/**
 * LDtk-Makro-Kompilierung: Liest zur Compile-Zeit die Datei "assets/data/map.ldtk"
 * ein und generiert typisierte Klassen und Enums für alle Level, Layer und Entities.
 */
private typedef _Tmp = haxe.macro.MacroType<[ ldtk.Project.build("assets/data/map.ldtk") ]>;

3. Spielstart in Main.hx

Haxe 
package;

import flixel.FlxGame;
import openfl.display.Sprite;

/**
 * Haupteinstiegspunkt der Anwendung.
 */
class Main extends Sprite {
    public function new() {
        super();
        addChild(new FlxGame(320, 180, PlayState, 60, 60, true, false));
    }
}
💡
Tipp zur Dead-Code-Elimination (DCE): Versehe deine dynamisch geladenen Entity-Klassen stets mit der Annotation @:keep, damit der Haxe-Compiler sie bei Release-Builds nicht wegoptimiert.

4. ⚡ Performance- & Hardware-Richtwerte

Dank der Zero-Allocation Render-Pipeline und der internen 160×90-Pixel-Basisauflösung ist mklib extrem ressourcenschonend. Richtwerte für konstante 60 FPS auf schwachen Office-Notebooks (Intel HD / UHD / Iris Xe iGPU):

Element Richtwert (Notebook / iGPU) Desktop-PC (GTX / RTX) Details
Sichtbare Sprites ~ 2.000 Sprites 20.000+ Sprites Hardware-Batching via OpenFL / Flixel DrawTiles
Nape Physik-Körper ~ 300 Bodies 3.000+ Bodies Aktive Rigid Bodies mit NAPE_RELEASE_BUILD
Shader-Lichtquellen 32 Lichter im Viewport 32 Lichter im Viewport Unbegrenzt im Level via Frustum Culling (autoCull)
⚡
Timing-Konfiguration in State.hx: FlxG.fixedTimestep = false (verhindert Nachhol-Lags), FlxG.maxElapsed = 0.05 (Notbremse bei Rucklern) und FlxG.autoPause = false (verhindert Einfrieren bei Fokusverlust).

🚀 Quick Start & Setup

Step-by-step guide to installing and integrating mklib into your HaxeFlixel project.

1. Dependencies in Project.xml

Add mklib and the required libraries to your Project.xml:

XML 
<haxelib name="openfl" />
<haxelib name="flixel" />
<haxelib name="flixel-addons" />
<haxelib name="nape-haxe4" />
<haxelib name="ldtk-haxe-api" />
<haxelib name="mklib" />

2. LDtk Macro Setup (Data.hx)

Create the file source/Data.hx. The macro analyzes your map.ldtk file at compile time and generates typed classes:

Haxe 
package;

/**
 * LDtk macro compilation: Reads "assets/data/map.ldtk" at compile time
 * and generates typed classes and enums for all levels, layers, and entities.
 */
private typedef _Tmp = haxe.macro.MacroType<[ ldtk.Project.build("assets/data/map.ldtk") ]>;

3. Game Entry Point in Main.hx

Haxe 
package;

import flixel.FlxGame;
import openfl.display.Sprite;

/**
 * Haupteinstiegspunkt der Anwendung.
 */
class Main extends Sprite {
    public function new() {
        super();
        addChild(new FlxGame(320, 180, PlayState, 60, 60, true, false));
    }
}
💡
Tipp zur Dead-Code-Elimination (DCE): Versehe deine dynamisch geladenen Entity-Klassen stets mit der Annotation @:keep, damit der Haxe-Compiler sie bei Release-Builds nicht wegoptimiert.

4. ⚡ Performance & Hardware Guidelines

Thanks to the zero-allocation rendering pipeline and 160×90 internal pixel base resolution, mklib is extremely lightweight. Target guidelines for rock-solid 60 FPS on low-end office laptops (Intel HD / UHD / Iris Xe iGPU):

Element Guideline (Laptop / iGPU) Desktop PC (GTX / RTX) Details
Visible Sprites ~ 2,000 Sprites 20,000+ Sprites Hardware batching via OpenFL / Flixel DrawTiles
Nape Physics Bodies ~ 300 Bodies 3,000+ Bodies Active rigid bodies with NAPE_RELEASE_BUILD
Shader Lights 32 lights in viewport 32 lights in viewport Unlimited in level via frustum culling (autoCull)
⚡
Timing configuration in State.hx: FlxG.fixedTimestep = false (prevents catch-up lags), FlxG.maxElapsed = 0.05 (failsafe clamp during lag spikes), and FlxG.autoPause = false (prevents focus-loss freeze).
