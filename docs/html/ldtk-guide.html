🗺️ LDtk Level-Editor Guide & Property-Referenz

Ausführliche Anleitung und vollständige Referenz aller Felder (Custom Fields), Enums, Layer-Typen und Lichteigenschaften im LDtk-Editor und deren automatische Verarbeitung in mklib.

🏷️

Enum „Tags“

Wird beim State-Start automatisch in Nape-CbTypes konvertiert und über Tags.get("...") bereitgestellt.

🖼️

TileRect Single Value

Schneidet Kacheln pixelgenau aus dem Tileset zu und erzeugt automatisch feste STATIC-Nape-Körper.

⚡

Sensor- & Bewegungs-Flags

sensor: true und allowMovement steuern Kollisions-Trigger und physikalische Trägheit ohne Code.

💡

GPU-Lighting Integration

Lichtquellen (Point, Spot, Torch, Glow) werden direkt aus LDtk-Entity-Feldern mit Radius, Farbe und Flackern erzeugt.

1. 🏛️ Architektur & Workflow

In mklib sind alle Leveldaten deklarativ im LDtk Level-Editor aufgebaut. Das offizielle Haxe LDtk-Makro (Data.hx) liest die Projektdatei zur Compile-Zeit aus und generiert typsichere Strukturen. Zur Laufzeit übernimmt mklib die vollautomatische Instanziierung:

Haxe Workflow 
class PlayState extends State<Data.Data_Level> {
    override public function create():Void {
        super.create();

        // 1. Initialisiert Nape & erzeugt CbTypes aus dem LDtk-Enum "Tags"
        napeInit(0, 0);

        // 2. Rendert Kachelebenen (Tiles / AutoLayer)
        add(new TileLayer(data.l_Tiles.identifier));
        add(new TileLayer(data.l_Props.identifier));

        // 3. Instanziiert alle Entities (sucht Klassen in "entities.*")
        add(new EntityLayer(data.l_Entities));
        add(new EntityLayer(data.l_HeroLayer));

        // 4. Erzeugt A* Navigationsraster aus IntGrid und Kacheln
        var navGrid = NavGridBuilder.autoBuild(data);

        // 5. Lädt GPU-Lichter (Point, Spot, Torch, Glow) aus LDtk-Entities
        var lighting = new LightingSystem(0xFF101018, 1.5);
        lighting.loadFromLevel(data);
        add(lighting);
    }
}

3. 🗺️ Layer-Typen in LDtk

In LDtk können drei Layer-Kategorien definiert werden, die von mklib unterschiedlich verarbeitet werden:

LDtk Layer-Typ Empfohlene Namen mklib Klasse Funktionsweise & Details
Tiles / AutoLayer Tiles, Background, Props, Foreground mklib.layer.TileLayer Rendert Kacheln über die native LDtk-Render-Pipeline in eine FlxSpriteGroup. Unterstützt Auto-Tiling und mehrere Kachelebenen.
Entities Entities, HeroLayer, Interactive mklib.layer.EntityLayer Durchsucht das Package entities.* nach passenden Klassennamen (z. B. Entity Hero → entities.Hero). Erzeugt automatisch EntityNapeSprite (bei Physikfeldern) oder EntitySprite (visuell). Prüft automatisch SaveManager auf zerstörte Objekte.
IntGrid Collisions, Walls, NavGrid mklib.path.NavGridBuilder Generiert das 2D-Raster für die A*-Pfadfindung. Werte != 0 werden als unpassierbare Rasterzellen markiert.

6. 💻 Eigene Custom Fields im Haxe-Code abfragen

Du kannst beliebige eigene Felder in LDtk anlegen (z. B. hp, dialogKey, targetLevel, isLocked, patrolPoints) und im Haxe-Code auf zwei Arten abrufen:

Custom Entity mit getField() 
package entities;

import mklib.entity.EntitySprite;
import ldtk.Entity;

@:keep
class Chest extends EntitySprite {
    public var isLocked:Bool = false;
    public var lootItemId:String = "potion";
    public var lootCount:Int = 1;

    public function new(entity:ldtk.Entity) {
        super(entity);

        if (hasField("isLocked")) {
            isLocked = getField("isLocked");
        }
        if (hasField("lootItemId")) {
            lootItemId = getField("lootItemId");
        }
        if (hasField("lootCount")) {
            lootCount = getField("lootCount");
        }
    }
}

7. 💾 Persistenz & Zerstörungs-Tracking mit iid

LDtk weist jeder Entity eine weltweit eindeutige iid (z. B. e3d4a5b6-7c8d-9e0f-1a2b-3c4d5e6f7a8b) zu. Der SaveManager von mklib nutzt diese ID, um aufgesammelte Münzen, besiegte Bosse oder geöffnete Truhen levelübergreifend zu merken.

Entity als zerstört markieren 
package entities;

import mklib.entity.EntityNapeSprite;
import ldtk.Entity;

@:keep
class Coin extends EntityNapeSprite {
    public function new(entity:ldtk.Entity) {
        super(entity);
    }

    public function collect():Void {
        // Speichert iid im SaveManager und ruft kill() auf
        markDestroyed();
    }
}
💡
Automatischer Respawn-Schutz: Wenn der Spieler ein Level erneut betritt, filtert EntityLayer zerstörte IIDs automatisch heraus. Aufgesammelte Gegenstände werden gar nicht erst geladen.

8. 🛠️ Schritt-für-Schritt-Anleitung: Von 0 zum fertigen Level

  1. LDtk Projekt erstellen: Speichere dein Projekt z. B. als assets/levels/world.ldtk. Importiere dein Tileset (z. B. assets/tilesets/dungeon.png, Kachelgröße 16x16).
  2. Enum "Tags" definieren: Lege unter Project Settings → Enums das Enum Tags mit den Werten Hero, Solid, Coin, Hazard, Checkpoint an.
  3. Layer anlegen: Erstelle Entities (Typ: Entities), Tiles (Typ: Tiles oder AutoLayer) und Collisions (Typ: IntGrid).
  4. Entities mit Custom Fields konfigurieren:
    • Hero: Field Tag = Hero.
    • Platform: Field Tag = Solid, Field TileRect = Tile (Single value).
    • Coin: Field Tag = Coin, Field sensor = true, Field Animations = "Coin".
    • Torch: Identifier Torch, Field color = #FFAA44, Field radius = 120, Field flickerIntensity = 0.2.
  5. Haxe State erstellen: Erbe von mklib.state.State<Data.Data_Level> und lade Ebenen, Physik und Beleuchtung.

GPU Lighting Integration

Light sources (Point, Spot, Torch, Glow) are spawned directly from LDtk entity fields with radius, color, and flicker parameters.

1. 🏛️ Architecture & Workflow

In mklib, all level data is built declaratively in the LDtk Level Editor. The official Haxe LDtk macro (Data.hx) reads the project file at compile-time and generates type-safe structures. At runtime, mklib handles automated instantiation:

Haxe Workflow 
class PlayState extends State<Data.Data_Level> {
    override public function create():Void {
        super.create();

        // 1. Initializes Nape & registers CbTypes from the LDtk enum "Tags"
        napeInit(0, 0);

        // 2. Renders tile layers (Tiles / AutoLayer)
        add(new TileLayer(data.l_Tiles.identifier));
        add(new TileLayer(data.l_Props.identifier));

        // 3. Instantiates all entities (scans package "entities.*")
        add(new EntityLayer(data.l_Entities));
        add(new EntityLayer(data.l_HeroLayer));

        // 4. Builds A* navigation grid from IntGrid and tile layers
        var navGrid = NavGridBuilder.autoBuild(data);

        // 5. Loads GPU lights (Point, Spot, Torch, Glow) from LDtk entities
        var lighting = new LightingSystem(0xFF101018, 1.5);
        lighting.loadFromLevel(data);
        add(lighting);
    }
}

2. 🏷️ Project-Wide Enum: Tags

The enum Tags is the core bridge between LDtk level objects and the Nape 2D Physics Collision System.

ℹ️
Where to create: In LDtk, click Project Settings (gear icon top-left) → Enums → New enum with identifier Tags (Case sensitive!).

Recommended Enum Values in LDtk:

Enum Value Typical Purpose Nape CbType Access in Code
Hero / Player Main player character Tags.get("Hero")
Solid / Obstacle Solid walls, floors, indestructible obstacles Tags.get("Solid")
Platform Moving or static platforms Tags.get("Platform")
Enemy Enemies and hostile NPCs Tags.get("Enemy")
Coin / Gem Collectible items / score pickups Tags.get("Coin")
Checkpoint Save points / respawn zones Tags.get("Checkpoint")
Door / Portal Level transitions and doors Tags.get("Door")
Hazard / Spikes Deadly traps, spikes, lava Tags.get("Hazard")
Water Water bodies / swimming areas / shader planes Tags.get("Water")

Collision and sensor callbacks are then bound using Listener:

Callback Binding 
// Solid collision between player and wall
Listener.addCollisionBeginListener(Tags.get("Hero"), Tags.get("Solid"), onHeroHitWall);

// Sensor overlap when collecting coins
Listener.addSensorBeginListener(Tags.get("Hero"), Tags.get("Coin"), onHeroCollectCoin);

3. 🗺️ Layer Types in LDtk

LDtk supports three layer categories that are handled automatically by mklib:

LDtk Layer Type Recommended Names mklib Class Behavior & Details
Tiles / AutoLayer Tiles, Background, Props, Foreground mklib.layer.TileLayer Renders tiles using LDtk's native render pipeline into a FlxSpriteGroup. Supports auto-tiling and multi-layer rendering.
Entities Entities, HeroLayer, Interactive mklib.layer.EntityLayer Scans the package entities.* for matching classes (e.g. entity Hero → entities.Hero). Automatically creates EntityNapeSprite (if physics fields exist) or EntitySprite (visual). Auto-checks SaveManager for destroyed items.
IntGrid Collisions, Walls, NavGrid mklib.path.NavGridBuilder Generates the 2D grid for A* pathfinding. Values != 0 are marked as solid impassable cells.

4. 📋 Full Entity Field Reference (Custom Fields)

The following custom fields can be configured in LDtk under Project Settings → Entities → (Select Entity) → Fields:

Field Name (Identifier) LDtk Field Type Supported In Default Value Effect in mklib

visible Boolean EntitySprite, EntityNapeSprite true Controls initial sprite visibility (sprite.visible) upon spawning.
alpha Float (0.0 to 1.0) EntitySprite, EntityNapeSprite 1.0 Controls sprite opacity / transparency (sprite.alpha).

7. 💾 Persistence & Destruction Tracking with iid

LDtk assigns a globally unique iid to every entity. The SaveManager in mklib uses this ID to persist destroyed enemies, collected coins, or opened chests across levels.

Mark Entity Destroyed 
package entities;

import mklib.entity.EntityNapeSprite;
import ldtk.Entity;

@:keep
class Coin extends EntityNapeSprite {
    public function new(entity:ldtk.Entity) {
        super(entity);
    }

    public function collect():Void {
        // Saves iid in SaveManager and calls kill()
        markDestroyed();
    }
}
💡
Automatic Respawn Protection: When re-entering a level, EntityLayer automatically filters out destroyed IIDs so collected items are never instantiated again.

  4. Configure Entities with Custom Fields:
    • Hero: Field Tag = Hero.
    • Platform: Field Tag = Solid, Field TileRect = Tile (Single value).
    • Coin: Field Tag = Coin, Field sensor = true, Field Animations = "Coin".
    • Torch: Identifier Torch, Field color = #FFAA44, Field radius = 120, Field flickerIntensity = 0.2.
  5. Create Haxe State: Inherit from mklib.state.State<Data.Data_Level> and load layers, physics, and lighting.
