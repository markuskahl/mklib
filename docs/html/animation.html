🎬 Animationssystem & Makros (mklib.animation.* & mklib.macro.*)

Automatisiertes Compile-Time-Laden von JSON-Spritesheet-Animationen ohne Laufzeit-Overhead.

1. Übersicht & Funktionsweise

Das Animationssystem von mklib besteht aus typsicheren Datenstrukturen (AnimationTypes), einem Compile-Time-Makro (AnimationBuilder) und einer zentralen Datenbank (AnimationRegistry).

📁

JSON Definitions

Clips, Frameraten und Rastermaße werden als übersichtliche .json-Dateien in assets/data/animations/ abgelegt.

⚡

Compile-Time Macro

AnimationBuilder.buildDatabase() liest alle JSONs beim Kompilieren ein, normalisiert Pfade und erzeugt ein getyptes Map-Literal.

🚀

Zero Runtime Cost

Kein JSON-Parsing zur Laufzeit. Entities greifen direkt auf die typisierte AnimationRegistry.db zu.

2. Datenstrukturen (mklib.animation.AnimationTypes)

FrameConfig

Konfiguriert Kachelabmessungen und Abstände auf dem Spritesheet.

Feld Typ Optional Beschreibung
width Int Nein Breite eines einzelnen Frames in Pixeln.
height Int Nein Höhe eines einzelnen Frames in Pixeln.
spacing Null<Int> Ja Abstand zwischen Frames in Pixeln.
margin Null<Int> Ja Äußerer Rand des Spritesheets in Pixeln.

AnimationClip

Definiert einen Animationsabschnitt mit Bildfolge, Geschwindigkeit und Wiederholung.

Feld Typ Optional Beschreibung
name String Nein Name des Clips (z. B. "burn", "walk").
fps Int Nein Abspielgeschwindigkeit (Frames pro Sekunde).
loop Bool Nein Endlosschleife aktivieren (true/false).
flipX Bool Nein Horizontale Spiegelung der Frames.
flipY Bool Nein Vertikale Spiegelung der Frames.
frames Array<Int> Nein Liste der Frame-Indizes (z. B. [0, 1, 2, 3]).

SpriteSheetData

Vollständiger Datensatz für ein animiertes Spritesheet.

Feld Typ Optional Beschreibung
imagePath String Nein Pfad zur Grafikdatei (z. B. "assets/tilesets/Fire.png").
config FrameConfig Nein Kachel- und Rastereinstellungen.
animations Array<AnimationClip> Nein Liste aller definierten Clips.
defaultAnimation String Nein Name des standardmäßig abzuspielenden Clips.

3. Compile-Time-Makro (mklib.macro.AnimationBuilder)

Methode Signatur Rückgabe Beschreibung
buildDatabase (folderPath:String):Expr Expr (Makro) Liest alle .json-Dateien im Ordner zur Compile-Zeit ein, normalisiert Asset-Pfade und generiert eine Map<String, SpriteSheetData>.

4. Die AnimationRegistry im Detail

Die Klasse AnimationRegistry (source/AnimationRegistry.hx) dient als globale Datenbank für alle Spritesheet-Animationen im Spielprojekt. Durch das Zusammenspiel mit dem Makro AnimationBuilder.buildDatabase werden alle Animationsdefinitionen bereits beim Kompilieren geparst und direkt als typisierter Code eingebettet.

💡
Compile-Time Transformation: Das Makro liest zur Compile-Zeit alle .json-Dateien aus assets/data/animations/ ein, wandelt absolute Pfade in relative assets/...-Pfade um und hinterlegt die Daten unter dem Dateinamen (z. B. "Fire" für Fire.json) in der statischen Map AnimationRegistry.db.

5. Praxis-Setup & Codebeispiele

1. JSON-Animationsdatei (assets/data/animations/Fire.json)

Definiert Bildquelle, Kachelmaße und beliebig viele Animationsclips:

JSON 
{
  "imagePath": "assets/tilesets/Fire.png",
  "config": {
    "width": 16,
    "height": 16,
    "spacing": 0,
    "margin": 0
  },
  "animations": [
    {
      "name": "burn",
      "fps": 12,
      "loop": true,
      "flipX": false,
      "flipY": false,
      "frames": [0, 1, 2, 3]
    }
  ],
  "defaultAnimation": "burn"
}

2. Registry-Klasse (source/AnimationRegistry.hx)

Definiert die zentrale Datenbank db, die beim Kompilieren mit allen Animationen befüllt wird:

Haxe 
package;

import mklib.animation.AnimationTypes;
import mklib.macro.AnimationBuilder;

@:keep
class AnimationRegistry {
    // Liest alle JSON-Dateien aus "assets/data/animations" zur Compile-Zeit ein
    public static var db:Map<String, SpriteSheetData> = AnimationBuilder.buildDatabase("assets/data/animations");
}

3. LDtk-Workflow: Das Enum Animations (Best Practice)

Um Tippfehler zu vermeiden und im Level-Editor ein komfortables Dropdown-Menü bereitzustellen, empfiehlt sich in LDtk die Verwendung eines Enums:

  1. Enum anlegen: Erstelle in LDtk unter Project Settings → Enums ein Enum namens Animations mit den Namen der Animationsdateien (z. B. Fire, Hero, Platform).
  2. Entity-Feld definieren: Füge der gewünschten Entity-Definition ein Feld namens Animations vom Typ Enum.Animations hinzu.
  3. Level platzieren: Wähle beim Platzieren der Entity im Level-Editor einfach die gewünschte Animation aus dem Dropdown-Menü aus.
ℹ️
Automatische Bindung: EntitySprite und EntityNapeSprite prüfen im Basis-Konstruktor automatisch mit hasField("Animations"), lesen den gewählten Enum-Wert als String aus (z. B. "Fire") und laden die Grafik sowie Clips direkt aus AnimationRegistry.db.

4. Entity-Klasse im Code (source/entities/Fire.hx)

Durch das gesetzte LDtk-Feld Animations ist im Code keinerlei manuelle Animationsinitialisierung nötig:

Haxe 
package entities;
 
import mklib.entity.EntitySprite;
import ldtk.Entity;
 
@:keep
class Fire extends EntitySprite {
    public function new(entity:ldtk.Entity) {
        // super(entity) liest getField("Animations") ("Fire") 
        // und lädt Grafik + Clips vollautomatisch aus AnimationRegistry.db!
        super(entity);
    }
}

5. Manuelles Laden & Wechseln auf Entities

Animationen können jederzeit auch manuell über den Schlüssel zugewiesen oder gewechselt werden:

Haxe 
// Lädt nachträglich oder wechselt das Animationsset auf "Fire":
myEntity.initAnimation("Fire");

// Manueller Wechsel des aktuellen Animationsclips:
myEntity.animation.play("burn");

5. Direkter Zugriff auf die Rohdaten

Für eigene Sprites oder Flixel-Objekte kann direkt auf die typisierte Map zugegriffen werden:

Haxe 
import AnimationRegistry;

var fireData = AnimationRegistry.db.get("Fire");
if (fireData != null) {
    trace("Grafikpfad: " + fireData.imagePath);          // "assets/tilesets/Fire.png"
    trace("Frame-Breite: " + fireData.config.width);     // 16
    trace("Default: " + fireData.defaultAnimation);      // "burn"
}
